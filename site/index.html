Put your actuator on the map

A small tool from our ARIA dexterous soft robotics work. Describe an actuator by datasheet numbers, a measured table, a formula or a mesh, and it becomes a record. The record goes on a map of actuators, drawn as the path its tip takes while its input rises. Once it is there, you can arrange copies of it as a manipulator and ask whether that manipulator can do a task.

The simulations and records here are not calibrated against real experiments unless marked.

Try it with no install

  • The actuator map draws every actuator we hold as the path its tip takes while its input rises, in three dimensions you can turn and choose. Pick an actuator to see its record and its force with the tip held. The finger simulated from a mesh further down this page is on it.
  • The record form takes datasheet numbers or a measured table, in whatever units you have, and gives you a record file to download, in browser.

First, your actuator on the map

The actuator is the piece to start with. It has several ways in, and each ends in the same plain file, a record. The commands below are run from the top folder of a clone, after the install.

Your actuator

Your actuator becomes a record, which is one file saying how the tip moves and how hard it pushes. A record is all the map needs, and one command puts it there.

From datasheet numbers, in your browser

Open the record form, type the numbers in whatever units you have, and download the record. The form needs no install. Putting the downloaded file on the map does.

From bench or simulation curves

The worked example is a published pneu-net bending actuator (data/test_curves/mosadegh2014_fPN.csv; the format is docs/TEST_CURVE_FORMAT.md).

python tools/curves_to_record.py data/test_curves/mosadegh2014_fPN.csv --out my_actuator.json
python tools/check_record.py my_actuator.json
python tools/figure_map_tip_paths.py --record my_actuator.json --tag my_actuator

The second command prints, among its lines:

     push direction  -   from no force data: this actuator cannot push in the tool
     stroke          94.9 mm

That file gives motion and no force, so its mark on the map is an open circle, which the legend reads as "motion only (no force data)". The full walk is docs/ADD_YOUR_ACTUATOR.md.

From an analytical model

Replace two functions in examples/analytical_model_to_curves.py with your formulas, and it writes the same table of curves a bench test would. As shipped it holds a textbook bending finger with made-up numbers.

python examples/analytical_model_to_curves.py --out my_model_curves.csv
python tools/curves_to_record.py my_model_curves.csv --out my_model.json
python tools/check_record.py my_model.json
python tools/figure_map_tip_paths.py --record my_model.json --tag my_model
From a table of joints, for a rigid finger 
python tools/joint_table_to_record.py data/joint_tables/shadow_hand_finger.csv --out my_finger.json
python tools/check_record.py my_finger.json
python tools/figure_map_tip_paths.py --record my_finger.json --tag my_finger

The format is docs/JOINT_TABLE_FORMAT.md. A record made this way goes on the map, but cannot yet be built into a hand (issue 33).

From a mesh, through a finite-element simulation

The scripts are in mesh_route/, with one worked pneu-net finger whose simulation runs are stored. So you can rebuild its record without a simulator. Runs of your own mesh need SOFA.

pip install -e ".[mesh]"
cd mesh_route
python preprocess.py cads/actuation_methods/pumped_volume_pneunet/mesh.msh cads/actuation_methods/pumped_volume_pneunet/actuator.npz
python sample_to_draft_record.py --sample experiments/actuation_methods/same_body_pneunet/chamber_pressure_set --cad cads/actuation_methods/pumped_volume_pneunet --id sample_pneunet_pressure_set --name "Pneunet, chamber pressure set (sample)" --physics pneumatic --input_name "chamber pressure (scene units)" --out_root ../my_mesh_drafts
cd ..
python tools/figure_map_tip_paths.py --record my_mesh_drafts/sample_pneunet_pressure_set.json --tag my_mesh

The last command draws the finger on a flat picture of the map, linked below. The steps, what each prints, and how to prepare your own mesh are in docs/ACTUATOR_FROM_A_MESH.md.

Your record on the map

This is the map, with every actuator we hold. Drag to turn it, choose what each axis shows, and pick an actuator to see its record. The finger simulated from a mesh above is on it. It also opens on a page of its own.

Whichever way your record was made, one command works out its place on this map and writes a small file. It needs scipy, which the install below brings.

python tools/export_map_paths.py --record my_actuator.json --tag my_actuator

It writes outputs/map_paths/map_own_records_my_actuator.json. On the map, choose that file under "Your own record". Your actuator is drawn with the others and marked "(yours)". The file stays in your browser and is sent nowhere. A record that holds only headline numbers, with no table of tip motion, has no path to draw, so it is left out and the map says so.

A second command draws a flat picture to keep or print. It needs matplotlib, which the install also brings.

python tools/figure_map_tip_paths.py --record my_actuator.json --tag my_actuator

It writes outputs/map_tip_paths/map_tip_paths_my_actuator.png, with the share of the tip's motion that is sideways across and the free stroke up, and your actuator boxed and labelled "(yours)". We keep the picture it drew for the mesh finger as an example.

Then a manipulator and a task

With the record on the map, two more pieces say what the actuator can do in a hand. A manipulator is an arrangement of fingers, and a task is what the object and its contacts must do. Each is again one plain file with more than one way in, and you can bring either one and keep ours for the other.

Your manipulator

Your manipulator becomes a hand, a file that says how many fingers there are and where each one stands.

From copies of your actuator 
python tools/build_record_hand.py examples/test_curve_hand/hand.json
python tools/add_hand.py examples/test_curve_hand/hand.xml examples/test_curve_hand/description.json

A short file says where each finger is mounted. The one here names my_actuator.json, the record made under "Bench or simulation curves" above, and the build needs the hands install (pip install -e ".[hands]"). Steps 4 to 6 of docs/PARTICIPANT_SCRIPT.md go through it.

From a hand you have a model of 
python tools/add_hand.py external/mujoco_menagerie/wonik_allegro/left_hand.xml examples/my_allegro_left.json

The model is a MuJoCo or URDF file, and a short description file says which body is each fingertip. This one is the Allegro hand, which python tools/fetch_hands.py fetches after the hands install. docs/BRING_YOUR_HAND.md says what a hand must have and gives the full steps.

Your task

Your task becomes a task file. It says, frame by frame, where the object is, which contacts touch it, where, and with what force.

From contacts in a MuJoCo simulation 
python examples/mujoco_contacts_to_leader.py
python tools/check_leader.py outputs/my_mujoco_task.json

This sample needs the hands install, which brings MuJoCo. It rests a ball on a ring of pads and writes its contacts as a task file. docs/TASK_FROM_MUJOCO.md shows how to adapt it to your own run and lists the traps.

From contacts in another simulator or an experiment

Your own script writes the same fields, which are listed in docs/TASK_FILE_FORMAT.md, under "Bringing your own task".

A hand and a task file go into the follow check (tools/run_follow.py), which says frame by frame whether that hand can be at those contacts with those forces. Check each file before using it, with tools/check_record.py for a record and tools/check_leader.py for a task file.

Install

You need Python 3.9 or newer and git. The last two lines make a record from the published bench curves and draw the map with it on. The line after them writes the file the browser map takes.

git clone https://github.com/geojenks/gramian-map-workshop
cd gramian-map-workshop
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[figures,map]"
python tools/curves_to_record.py data/test_curves/mosadegh2014_fPN.csv --out my_actuator.json
python tools/figure_map_tip_paths.py --record my_actuator.json --tag my_actuator
python tools/export_map_paths.py --record my_actuator.json --tag my_actuator

To check rigid robot hands as well (Allegro, Shadow, LEAP and Linker's public L20), add MuJoCo and fetch the hand models:

pip install -e ".[hands]"
python tools/fetch_hands.py

The README explains how to read a result, what data a record needs, and where every number comes from. Each push is checked on clean Linux and Windows machines.
