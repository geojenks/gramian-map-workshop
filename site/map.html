Actuator map

Actuator map

Each line is the tip of one actuator. It starts at rest and moves as the input rises. Across the three axes you choose, the direction of a line says what kind of motion the actuator makes. Its length says how much.

Axes that measure the same kind of thing share one scale.

What each axis shows

How each is measured

    Your own record

    The map can show an actuator of your own beside ours. In a clone of the repository, run python tools/export_map_paths.py --record my_actuator.json --tag mine and choose the file it writes. The file stays in this browser and is sent nowhere.

    Task

    The map can test the actuators against a task of your own. Copy data/tasks/cup_turn.json, give it an id of its own and change the ball, the friction, the contact ring or the duty. Then run python tools/export_map_paths.py --task my_task.json --tag mine and choose the file it writes. It joins the list above. The finger count, the half-angle and the stroke angle are carried over from our task. With the finger on the palm, only the ball's radius and the height of the contact ring change the result, because that placement tests no push. With the finger aimed at the ball, the ball's mass also changes the push the task needs. The file stays in this browser and is sent nowhere.

    A task can also be given as a target on the map's own axes: a file that states values, or ranges of values, on any of the axes. The page draws it as a point, a line, a surface or a box, depending on which of its axes are among the three shown. It is drawn beside the paths, and no actuator is tested against it. docs/MAP_TARGET_FORMAT.md gives the form of the file. To make one from the task file of a simulation, run python tools/leader_to_map_target.py my_task.json --tag mine. Choose either kind of file here.

    Input

    100%

    Every actuator is shown at the same share of its own input range. Their inputs are in different units, so there is no common input to plot.
